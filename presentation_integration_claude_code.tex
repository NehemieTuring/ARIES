\section{Objectif}

\begin{frame}{Objectif}
Ajouter \textbf{Claude Code} comme troisième harness dans ARIES (aux côtés
d'OpenClaw et Hermes) : le faire tourner sur de vraies tâches
Terminal-Bench 2 et comparer sa télémétrie (durée, CPU, mémoire) et sa
fiabilité aux deux autres, dans les mêmes conditions.
\end{frame}

% ============================================================
\section{Démarche}

\begin{frame}{Où s'insère un nouveau harness dans ARIES}
\begin{itemize}
  \item ARIES ne parle jamais directement au modèle : chaque harness
        (OpenClaw, Hermes, et maintenant Claude Code) appelle lui-même son
        API --- ARIES orchestre, isole, mesure.
  \item Un harness s'exécute dans son propre conteneur ; ses outils (Bash,
        édition de fichiers) passent par un \textbf{pont SSH} vers le sandbox
        de la tâche --- jamais d'accès direct.
  \item Avant l'évaluation, le harness est arrêté et le pont révoqué
        (\emph{fail-closed}) : aucun accès résiduel au sandbox pendant que le
        vérificateur travaille.
\end{itemize}
\vspace{0.3cm}
Intégrer Claude Code = écrire ce pont pour lui, sans rien changer au reste
du framework.
\end{frame}

\begin{frame}{Trois défis, trouvés et résolus en testant contre le vrai outil}
\begin{enumerate}
  \item \textbf{La grammaire réelle de l'outil Bash} n'est pas documentée ---
        capturée en observant un vrai Claude Code (5 formes d'invocation
        différentes), puis le pont réécrit en conséquence.
  \item \textbf{L'authentification} non interactive a nécessité d'inverser
        empiriquement le bon mécanisme (\texttt{apiKeyHelper} lisant un
        fichier, pas une variable d'environnement) et, pour les clés API
        récentes, un header \texttt{workspace-id} supplémentaire.
  \item \textbf{Write/Read/Edit natifs} de Claude Code écrivent dans le
        conteneur du harness, jamais dans le sandbox --- contourné par un
        serveur MCP personnalisé qui redirige ces outils vers le même pont
        que Bash.
\end{enumerate}
\vspace{0.2cm}
Chaque point a été validé contre une vraie infrastructure (Docker, SSH,
Claude Code, vraie clé API) --- pas seulement relu.
\end{frame}

\begin{frame}[fragile]{Code livré}
\begin{lstlisting}
pkg/harness/claudecode/     Start / Run / Stop, authentification, wrapper bash
pkg/bridge/claudecodessh/   pont SSH : grammaire Bash + routage fichiers
cmd/aries-claudecode-mcpfiles/  serveur MCP (write_file/read_file/edit_file/
                                 glob/grep), redirige vers le pont

                                 n'existe : Claude Code n'est distribue qu'en

\end{lstlisting}

\texttt{cmd/aries/wiring.go} (nouveau harness/pont), \texttt{pkg/config}
(backend \texttt{anthropic}).

\vspace{0.2cm}
Documentation complète et détaillée : \texttt{rapport\_integration\_claude\_code.md}.
\end{frame}

\section{Résultat}

\begin{frame}[fragile]{Un run réel sur une vraie tâche Terminal-Bench 2}
\texttt{./bin/aries profiles/claudecode-tb2-fix-git-anthropic.json} sur
\texttt{fix-git-001} --- toute la chaîne ARIES, de bout en bout :

\vspace{0.3cm}
\begin{lstlisting}
harness_status: succeeded
isolation: confirmed (harness stoppe + pont revoque avant evaluation)
evaluation_status: succeeded (score 1)
observer: succeeded, telemetrie echantillonnee chaque seconde
\end{lstlisting}

\texttt{monitor/resources.jsonl} utilise le même schéma exact que les runs
OpenClaw/Hermes --- \textbf{directement comparable, sans transformation}.
C'était l'objectif final du stage.
\end{frame}

\begin{frame}{Le pont refuse une commande : que se passe-t-il ?}
Un run a révélé que la grammaire du pont rejetait à tort une commande Bash
légitime : Claude Code utilisait un idiome POSIX de guillemets imbriqués
(\texttt{'"'"'}) que le décodeur ne connaissait pas.

\vspace{0.3cm}
\textbf{Ce qui s'est passé} : le pont a refusé la commande (\emph{fail-closed},
correct par construction) $\rightarrow$ l'agent s'est rabattu sur les outils
MCP \texttt{write\_file}/\texttt{edit\_file} $\rightarrow$ \textbf{la tâche a
réussi quand même}.

\vspace{0.3cm}
\textbf{Deux enseignements} :
\begin{itemize}
  \item Le système reste correct même quand une commande légitime est refusée
        à tort --- il se dégrade, il ne casse pas.
  \item Une grammaire trop stricte a un coût mesurable : après correction,
        la même tâche passe de \textbf{39 s à 7,6 s} et n'emprunte plus du
        tout la voie MCP.
\end{itemize}
\end{frame}

\section{Comparaison avec OpenClaw et Hermes}

\begin{frame}{Une limite de protocole à énoncer d'emblée}
Les trois harnesses ne tournent pas sur le même modèle :

\vspace{0.3cm}
\begin{center}
\renewcommand{\arraystretch}{1.3}
\begin{tabular}{ll}
\toprule
Harness & Modèle \\
\midrule
OpenClaw    & DeepSeek \\
Hermes      & DeepSeek \\
Claude Code & Claude Sonnet 5 \\
\bottomrule
\end{tabular}
\end{center}

\vspace{0.4cm}
Les écarts mesurés ci-après mélangent donc \textbf{l'effet du harness et
celui du modèle} : ils ne permettent pas de les séparer. Un protocole à
modèle constant (même modèle pour les trois harnesses, via
\texttt{ANTHROPIC\_BASE\_URL}) est la prochaine étape --- l'architecture
d'ARIES le permet sans modification.
\end{frame}

\begin{frame}{fix-git-001 --- n=5 par harness, moyenne $\pm$ écart-type}
\begin{center}
\renewcommand{\arraystretch}{1.3}
\begin{tabular}{lcccc}
\toprule
Harness & Résultat & Durée & Pic CPU & Mémoire \\
\midrule
OpenClaw     & 4/5 réussi & 121,8 $\pm$ 27,6 s & 259,2 $\pm$ 5,1\%  & 671,9 $\pm$ 79,3 Mo \\
Hermes       & 5/5 réussi & 152,4 $\pm$ 36,2 s & 97,7 $\pm$ 3,3\%   & 230,0 $\pm$ 39,7 Mo \\
Claude Code  & 4/5 réussi & 113,0 $\pm$ 19,2 s & 56,4 $\pm$ 41,2\%  & 189,7 $\pm$ 55,9 Mo \\
\bottomrule
\end{tabular}
\end{center}

\vspace{0.4cm}
À n=5, seuls les écarts grands devant l'écart-type comptent :
\textbf{OpenClaw et Hermes tournent sur le même modèle} --- leur écart de CPU
et mémoire (2,5-3$\times$) est donc imputable au harness seul, pas au modèle.
Claude Code vs OpenClaw en durée (113 s contre 122 s) : indiscernable du
bruit à cet échantillon.
\end{frame}

\begin{frame}{overfull-hbox-001 --- n=5 par harness, moyenne $\pm$ écart-type}
\begin{center}
\renewcommand{\arraystretch}{1.3}
\begin{tabular}{lcccc}
\toprule
Harness & Résultat & Durée & Pic CPU & Mémoire \\
\midrule
OpenClaw     & \textbf{2/5 réussi} & 895,1 $\pm$ 69,3 s  & 259,3 $\pm$ 11,3\% & 621,8 $\pm$ 100,9 Mo \\
Hermes       & 5/5 réussi          & 791,8 $\pm$ 60,1 s  & 97,4 $\pm$ 4,4\%   & 265,1 $\pm$ 41,7 Mo \\
Claude Code  & 4/5 réussi          & \textbf{455,7 $\pm$ 85,5 s} & 113,6 $\pm$ 6,7\%  & 237,6 $\pm$ 61,3 Mo \\
\bottomrule
\end{tabular}
\end{center}

\vspace{0.4cm}
Trois résultats qui tiennent face au bruit : \textbf{OpenClaw ne réussit que
2 fois sur 5} (contre 5/5 pour Hermes, même modèle) --- invisible à n=1 ;
Claude Code reste nettement plus rapide (écart de 300+ s pour des
écarts-types de 60-86 s) ; OpenClaw consomme toujours plus de CPU/mémoire que
Hermes, à modèle égal.
\end{frame}

\begin{frame}{Le résultat le plus solide : la fiabilité d'OpenClaw sur cette tâche}
OpenClaw et Hermes partagent le \textbf{même modèle} (DeepSeek) et la même
tâche --- leur écart de fiabilité (2/5 contre 5/5) est donc un effet de
harness mesuré \textbf{sans confusion de modèle} : le résultat comparatif le
plus solide et le plus actionnable de cette campagne.

\vspace{0.4cm}
Pas encore diagnostiqué --- pistes immédiates : l'agent a-t-il cru réussir à
tort (comme observé une fois pour Claude Code) ou a-t-il authentiquement
échoué à éliminer les avertissements ? Comparer les trajectoires des runs
échoués et réussis pour une différence de stratégie.
\end{frame}

\begin{frame}{Ce que ces deux tâches montrent --- et ce qu'elles ne montrent pas}
\textbf{Ce qui est solide} :
\begin{itemize}
  \item L'intégration fonctionne de bout en bout sur de vraies tâches, sur
        30 runs réels, avec une télémétrie comparable dans le même schéma.
  \item OpenClaw vs Hermes (même modèle) : écart de CPU/mémoire net, et un
        écart de fiabilité important sur \texttt{overfull-hbox-001}.
  \item Claude Code : nettement plus léger en CPU/mémoire qu'OpenClaw sur les deux
        tâches ; l'écart avec Hermes n'est pas significatif. Plus rapide sur l'une,
        indiscernable de l'autre sur la seconde.
\end{itemize}

\vspace{0.3cm}
\textbf{Ce qui reste à établir} :
\begin{itemize}
  \item Tout écart impliquant Claude Code mélange encore l'effet du harness
        et celui du modèle (Sonnet 5 contre DeepSeek).
\end{itemize}

\vspace{0.3cm}
Comparaison interactive complète (30 runs réels, deux tâches, table
détaillée) : voir \texttt{comparaison\_harnesses.html} joint au rapport.
\end{frame}

\section{Pour la suite}

\begin{frame}{Ce qui reste, par ordre de priorité}
\begin{enumerate}
  \item \textbf{Diagnostiquer l'échec de fiabilité d'OpenClaw} sur
        \texttt{overfull-hbox-001} (2/5) --- le résultat le plus solide et le
        plus actionnable, mesuré sans confusion de modèle.
  \item \textbf{Protocole à modèle constant pour Claude Code} --- faire
        tourner Claude Code sur le même modèle qu'OpenClaw/Hermes (ou
        l'inverse) achèverait d'isoler l'effet du harness. Aucun code
        nouveau nécessaire.
  \item \textbf{Élargir à d'autres tâches}, maintenant que la méthode (n=5,
        moyenne $\pm$ écart-type) est en place et a fait ses preuves sur deux
        tâches.
  \item \textbf{Épinglage de version comme condition de reproductibilité} ---
        la grammaire Bash est rétro-conçue sur Claude Code 2.1.245, qui se met
        à jour automatiquement. L'image est épinglée
        (\texttt{aries-claudecode:2026.09.03}) ; un test de non-régression
        rejouant les formes observées reste à ajouter.
  \item \textbf{\texttt{edit\_file} au-delà de \textasciitilde98 Ko par
        chaîne} --- plafond de paquet SSH, cause identifiée, correctif connu
        (streamer sur stdin). Ne bloque rien en pratique.
\end{enumerate}
\end{frame}

\begin{frame}{Questions pour discussion}
\begin{itemize}
  \item L'intégration est validée de bout en bout sur deux tâches réelles,
        n=5 par harness --- suffisant pour clore cette partie du stage ?
  \item Vaut-il mieux diagnostiquer l'écart de fiabilité OpenClaw d'abord,
        ou lever la confusion de modèle sur Claude Code d'abord ?
  \item Puis-je disposer d'un accès modèle permettant de faire tourner les
        trois harnesses sur le même modèle ?
\end{itemize}
\end{frame}
